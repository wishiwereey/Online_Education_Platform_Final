# Online Education Platform
## Zhasmira Mamyrbayeva, Aidana Muratova
## SE-2539
An application for an online learning platform: instructors build courses and
publish assignments, students enroll with paid add-ons, submit work, get graded, receive
notifications and course recommendations.

The project integrates 6 design patterns:

| Student  | Pattern | Where | What it does in the platform |
|----------|---|---|---|
| Aidana   | Builder | builder/Course, Course.Builder, CourseDirector | Step-by-step creation of courses (modules, quizzes, tags, price, level) |
| Aidana   | Factory Method | factory/AssignmentFactory + 4 concrete creators | Creating assignments: quiz, essay, coding task, project |
| Aidana   | Decorator | decorator/CourseAccessDecorator + 4 decorators | Paid add-ons on course access: certificate, mentor, offline, subtitles |
| Zhasmira | Observer | observer/NotificationCenter, LearningObserver + 4 observers | Notifications: e-mail, push, instructor dashboard, progress tracker |
| Zhasmira | Strategy | strategy/RecommendationStrategy + 4 strategies, RecommendationEngine | Course recommendations: popular, by interests, by level, by budget |
| Zhasmira | Facade | facade/LearningPlatformFacade | One simple API for learning management over 6 subsystems |

## Running the Project
- Main.java — entry point that starts the application.
- EducationApp.java — JavaFX graphical interface of EduFlow.
- DemoData.java — generates sample courses and students for testing.

To run: mvn clean javafx:run

## How the Patterns Work Together
The Online Education Platform integrates six design patterns into one application: Builder, Factory Method, Decorator, Facade, Observer, and Strategy.
Instead of working independently, these patterns cooperate to support course creation, student registration, enrollment, assignments, notifications, and personalized recommendations.

### 1. Facade, Central Access Point
The LearningPlatformFacade acts as the main entry point for the application.
The JavaFX interface communicates with the Facade instead of accessing individual services directly.
Main operations:
- publishCourse() — publishes a course.
- registerStudent() — registers a student.
- enroll() — enrolls a student in a course.
- createAssignment() — creates an assignment.
- submit() — submits student work.
- grade() — grades an assignment.
- recommend() — generates course recommendations.
- notifications() — provides access to notifications.

Benefit: Reduces coupling between the user interface and business logic.

### 2. Builder, Course Creation
The Builder pattern creates complex Course objects step by step.
A course can include an instructor, difficulty level, price, modules, lessons, quizzes, and tags.

How it connects: Builder constructs the course, and Facade publishes it to the platform.

Benefit: Makes course creation readable, flexible, and easy to extend.

### 3. Factory Method, Assignment Creation
The Factory Method pattern creates different types of assignments without exposing their construction logic to the user interface.

Supported assignment types:
- Quiz
- Essay
- Coding assignment
- Project

How it connects: Facade delegates assignment creation to the appropriate Factory Method creator.

Benefit: New assignment types can be added without changing the main application logic.

### 4. Decorator, Course Add-ons
The Decorator pattern dynamically extends course access with optional features.

Available add-ons:
- Certificate
- Mentor support
- Offline access
- Subtitles

Each selected add-on wraps the existing CourseAccess object and contributes to the final price.

The final price is calculated from the base course price and the selected decorators.

How it connects: Facade coordinates course enrollment, while Decorator applies additional features and calculates the customized price.

Benefit: Supports multiple combinations of add-ons without creating a separate course subclass for each combination.

### 5. Observer, Events and Notifications
The Observer pattern handles communication between platform services through events.

When important actions occur, services publish events that registered observers can process.

Example events:
- Student registration
- Course enrollment
- Assignment submission
- Assignment grading

Notifications generated by these events are stored in NotificationLog.

The JavaFX Notifications screen displays the stored messages.

How it connects: Business services generate events, and Observer handles notifications independently of the original operation.

Benefit: Reduces dependencies between services and notification handling.

### 6. Strategy, Course Recommendations
The Strategy pattern allows the platform to switch between different recommendation algorithms at runtime.

Available strategies:

| Strategy | Purpose |
|---|---|
| PopularityStrategy | Recommends popular courses |
| InterestBasedStrategy | Matches courses to student interests |
| LevelBasedStrategy | Considers student difficulty level |
| BudgetStrategy | Considers the student's budget |

The recommendation algorithm can be changed without modifying the Facade or course classes.

How it connects: Facade delegates recommendation requests to the currently selected Strategy.

Benefit: Recommendation algorithms are interchangeable and independently extensible.

### Complete Application Workflow
The following workflow demonstrates how all six patterns cooperate:

1. Course creation — Builder: An instructor creates a course with modules, lessons, quizzes, and other properties.
2. Course publication — Facade: The completed course is published and becomes available in the Course Catalog.
3. Student registration — Facade: A student registers and provides learning interests.
4. Course recommendations — Strategy: The platform selects suitable courses using the active recommendation algorithm.
5. Course customization — Decorator: The student selects optional add-ons, and the platform calculates the customized price.
6. Enrollment — Facade: The student enrolls in the selected course with the chosen add-ons.
7. Assignment creation — Factory Method: An instructor creates an assignment of the required type.
8. Submission and grading — Facade: The student submits work, and the instructor grades it.
9. Notifications — Observer: Platform events trigger notifications that can be viewed in the Notifications section.

## Testing
The project uses JUnit 5 for unit and integration testing. Six test classes verify the implementation of all GoF design patterns and the main platform workflows.

| Test Class | What It Tests |
|---|---|
| BuilderTest | Course creation, default values, validation, immutability, and CourseDirector |
| FactoryMethodTest | Quiz, Essay, Coding, and Project assignment creation, deadlines, scores, and unique IDs |
| StrategyTest | Recommendations by popularity, interests, level, and budget; strategy switching |
| DecoratorTest | Course pricing, combining add-ons, and additional features |
| ObserverTest | Event subscriptions, notifications, unsubscribing, and dashboard event counts |
| FacadeIntegrationTest | Enrollment, payments, notifications, grading, course completion, reminders, and recommendations |

Run all tests: mvn clean test

The tests are located in src/test/java and help verify that the platform's components work correctly both independently and together.

## Benefits of the Architecture
- Modularity: Each pattern has a clearly defined responsibility.
- Loose coupling: The UI communicates primarily through the Facade.
- Extensibility: New courses, assignment types, add-ons, and strategies can be introduced with minimal changes.
- Maintainability: Components can be updated and tested independently.
- Reusability: Pattern implementations can be reused across the platform.
- Runtime flexibility: Recommendation strategies and course add-ons can be changed dynamically.

## Summary
All six design patterns are integrated into a single educational platform.
The Builder creates courses, Factory Method creates assignments, Decorator customizes course access, Observer handles notifications, Strategy generates recommendations, and Facade coordinates the system.
Together, they demonstrate how design patterns can be combined to build a flexible, maintainable, and extensible Java application.
